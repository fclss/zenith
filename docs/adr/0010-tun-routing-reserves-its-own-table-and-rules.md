# TUN routing reserves its own table and rule indices

TUN mode pins `iproute2_table_index: 1024` and `iproute2_rule_index: 8000`, deliberately away from nekobox's table 2022 and rules 9000-9010 so the two clients can run side by side. Cleanup only ever touches zenith's own interface, table, and rule indices; it never removes other clients' rules, even when they look orphaned. Considered: sing-box's defaults (rejected: collide with or shadow nekobox), deleting stale `tun_*` interfaces at connect (rejected: a lingering `tun_*` normally means a *live* other client, since the kernel destroys TUN devices when their owner exits), flushing other clients' rules (rejected: broke a live nekobox tunnel). Consequence: zenith must not run alongside another client that also claims table 1024 or rule index 8000.
