# TUN runs on the gvisor stack

TUN mode pins `stack: "gvisor"` so sing-box's userspace TCP/IP stack handles both TCP and UDP. The alternatives, `system` and `mixed`, hand TCP to the kernel stack, which only sees intercepted packets if something feeds them back in via firewall redirection (TPROXY, `REDIRECT`, or `auto_redirect`). On this host the firewall is nftables owned by ufw, which blocks or conflicts with sing-box's redirection rules — UDP/DNS (gvisor) worked while TCP (system) timed out. Considered: `mixed` (rejected: TCP timed out under ufw), `system` (same, and deprecated), `auto_redirect` (rejected: fights ufw's nftables chains). Consequence: we trade peak throughput for needing no firewall cooperation at all; at VPN speeds the tunnel, not the local stack, is the bottleneck.
